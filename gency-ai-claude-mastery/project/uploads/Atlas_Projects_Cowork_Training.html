Deep Dive

Cowork — Your Autonomous Work Partner

Cowork isn't just a chat with file access. It's Claude working independently on complex tasks while you do other things.

1

Give It a Task

Describe what you need — a report, a presentation, a data analysis, a batch of emails. Be specific about format, audience, and requirements.

"Create a 10-slide deck for our Q2 kickoff using the Atlas PPT template. Audience: AEs and SDRs."

2

Claude Works Autonomously

Claude reads your project files, activates relevant skills, executes multi-step workflows, creates files, and validates output — without needing you to guide each step.

You can close the window and come back later. Cowork keeps working.

3

Review & Iterate

Claude delivers finished output saved to your project folder. Review it, give feedback ("make the intro more punchy"), and Claude refines — building on what it already did.

Iterate the 20% — don't restart from scratch.

Key difference from Chat: In Chat, Claude responds to each message. In Cowork, Claude plans and executes — reading files, running code, creating documents, and making decisions along the way. It's the difference between answering questions and doing the work.

Getting Started — 5 Steps

Set this up once, and every future conversation starts smarter.

Install Desktop App

Download from claude.com/download. Log in with your Pro, Max, or Team account. You'll see Chat and Cowork tabs at the top.

Projects

Projects — Your Dedicated Workspace

Projects are the organizational backbone of Cowork. Each project is a dedicated context with its own folder, instructions, memory, and tasks.

What Lives Inside a Project

  • Working folder — a local directory Claude reads from and saves to
  • Project instructions — custom rules specific to this project
  • Memory — Claude builds knowledge over time. Preferences, decisions, context persist across conversations
  • Scheduled tasks — recurring automations (weekly reports, daily summaries)
  • Conversation history — past conversations stay scoped to the project
  • Skills — all installed skills are available in every project

Project Setup Best Practices

One project per workstream. Don't dump everything into one project. Create separate ones for "Q1 Campaign", "Sales Enablement Content", "RevOps Reporting", etc.

Add context files to the folder. Drop brand guidelines, ICPs, past examples, messaging docs, templates — anything Claude should reference. More context = better output.

Write clear project instructions. Tell Claude who the audience is, what standards to follow, what format outputs should take, and what to avoid.

Keep it organized. Use subfolders — /drafts, /final, /data. Claude respects your folder structure.

Memory

Memory — Claude Gets Smarter Over Time

Claude automatically saves patterns, preferences, and decisions. No manual setup required.

Four Types of Memory

User Memories

Your role, expertise, how you like to work. Claude tailors responses based on who you are.

Feedback Memories

Corrections and confirmed approaches. "Never use green" or "yes, the single PR was right" — Claude remembers both.

Project Memories

Deadlines, stakeholders, decisions. "Q2 campaign launches April 15" — Claude factors this in automatically.

Reference Memories

Where to find external info. "Pipeline bugs are tracked in Linear project INGEST" — Claude knows where to look.

How to Use Memory

Teach Claude explicitly

"Remember that our Q2 campaign launches April 15"

"Remember that I prefer bullet points over paragraphs"

"Forget the old positioning doc — we updated it"

Let Claude learn naturally

When you say "that was perfect" or "never do that again", Claude saves it. Feedback compounds — your 50th conversation is dramatically better than your 1st.

Memory persists across conversations within a project. Start a new conversation next week, and Claude still remembers your preferences, past decisions, and team context.

Memory is per-project. Different projects can have different memories. Your "Q1 Campaign" memory doesn't bleed into "Sales Enablement."

Template

Global Instructions — Copy & Customize

Paste this into Settings → Cowork → Global Instructions. Edit the bracketed sections for your role.

# About Me I'm [Your Name], [Your Role] at Atlas HXM. I work across [your teams/functions]. Based in [location]. Started [date]. # Communication Style - Be concise and direct — I value speed - Use bullet points over long paragraphs - Flag decisions that need my input vs. decisions you can make autonomously - Don't over-explain obvious things # Output Preferences - Save documents as .docx or .pptx - Use Atlas brand voice (atlas-brand-guidelines) - Gelion font preferred, Poppins as fallback - Never use green in branded materials - Always proofread before saving final output # Tools & Context - CRM: [HubSpot/Salesforce] - Sequencing: [Outreach/Apollo/Salesloft] - Internal comms: [Slack/Teams] - Project mgmt: [Asana/Linear/Jira]

Why This Matters

Without global instructions, every conversation starts from zero. Claude doesn't know your role, preferences, or team context.

With global instructions: Claude already knows you're a GTM Manager who wants .docx outputs in Atlas brand voice. Every response is tailored from the start.

Dos & Don'ts

✅ Include your role and team

✅ Specify output format preferences

✅ Mention tools your team uses

❌ Don't include sensitive data (passwords, API keys)

❌ Don't make it too long — focus on what changes behavior

Prompting

The CRAFT Framework for Better Prompts

The quality of output directly reflects the quality of your input.

Context — Who you are, what project, who the audience is

Role — Tell Claude what role to play: "You are an Atlas content strategist"

Action — What specifically you want done: "Write a 300-word blog intro"

Format — How you want the output: "As a .docx with H2 headers"

Tone — Specify the voice: "Authoritative but not formal, per Atlas brand"

Weak vs. Strong

❌ Weak

"Write a blog post about EOR"

"Make a presentation"

✅ Strong

"Write a 600-word blog post targeting HR Directors at mid-market companies considering their first international hire. Focus on top 3 compliance risks of hiring in Germany. Use Atlas brand voice. Save as .docx."

"Create a 10-slide .pptx deck for our Q2 sales kickoff. Audience: AEs and SDRs. Cover new messaging, updated ICP, competitive positioning. Use the Atlas PPT template."

In Cowork, you can be even more specific because Claude has your project context, files, and memory. "Use the data in /data/q1-results.xlsx" works.

Important

Security, Compliance & Data Handling

Claude is powerful but requires responsible use — especially at a company handling global HR and compliance data.

What NOT to Share with Claude

  • PII / employee data — SSN, passport, salary, medical info
  • Client contracts & financials — unless explicitly approved by Legal
  • Credentials & passwords — API keys, login credentials, tokens
  • Confidential strategy docs — board materials, M&A info, unreleased financials

Rule of thumb: If you wouldn't email it to an external consultant, don't share it with Claude.

Best Practices

  • Review before sharing externally — always check output for accuracy and data exposure
  • Use Team/Enterprise plans for admin controls, SSO, and data governance
  • Don't publish artifacts with internal metrics, client names, or strategic data
  • Check connector permissions — understand what data Claude can access
  • Report concerns to your manager or IT

Best Practices

10 Rules for Getting the Most from Cowork

1. Be specific, not vague. Include audience, format, word count, tone. The more detail, the better the first draft.

2. Use Projects — always. Never work in a bare conversation. Projects give Claude persistent context.

3. Front-load context. Drop brand docs, ICPs, examples into your project folder before asking for outputs.

4. Iterate, don't restart. If the first output is 80% right, ask Claude to fix the 20%. Don't start a new conversation.

5. Give feedback to build memory. Say "that was perfect" or "never do X again." Claude remembers and improves.

6. Schedule recurring work. Weekly competitive briefs, daily pipeline summaries. Set once, get forever.

7. Combine skills for complex tasks. "Brand guidelines AND presentations" produces better results than either alone.

8. Use Chat for quick things. Don't burn Cowork tokens on simple questions. Chat is faster for brainstorming.

9. Review before sharing. Always check output for accuracy, brand compliance, and confidential data.

10. Share your setup. Share project instructions and skills with teammates. Same setup = consistent team output.
