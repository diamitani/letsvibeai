What Is a Skill?

A skill is a set of instructions — packaged as a simple folder — that teaches Claude how to handle specific tasks or workflows.

The Core Idea

Instead of re-explaining your preferences, processes, and domain expertise in every conversation, skills let you teach Claude once and benefit every time.

  • Skills are persistent — they don't expire after a conversation
  • Skills activate automatically when Claude detects a matching task
  • Multiple skills can combine for a single task
  • Skills work across Claude.ai, Claude Code, and API

Think of skills as SOPs for Claude. What instructions would you give a new hire to do this task perfectly every time? That's your skill.

What's Inside a Skill Folder

your-skill-name/ ├── SKILL.md # Required — main instructions ├── scripts/ # Optional — executable code │ ├── process_data.py │ └── validate.sh ├── references/ # Optional — docs loaded on demand │ └── api-guide.md └── assets/ # Optional — templates, fonts, icons └── report-template.md

Only SKILL.md is required. Everything else is optional. You can start with just a single markdown file and add complexity later.

Core Concept

Progressive Disclosure — How Skills Load

Skills use a three-level system to minimize token usage while maintaining deep expertise.

1

YAML Frontmatter

Always loaded in Claude's system prompt. Provides just enough info for Claude to know when to use the skill — without loading everything.

---
name: atlas-email
description: Cold outbound email
  sequences for Atlas HXM...
---
2

SKILL.md Body

Loaded when triggered. Contains the full instructions, rules, templates, and guidance. This is the meat of the skill.

# Atlas Email Skill
## Voice & Tone
- Authoritative, inclusive
## Templates
### Cold Outreach
[Hook] [Value] [CTA]
3

Linked Files

Loaded on demand. Additional files in references/, scripts/, and assets/ that Claude discovers only when needed.

references/
  brand-visual.md
  content-examples.md
assets/fonts/
  Gelion-Regular.otf

Why this matters: A skill with 5,000 words of instructions doesn't load all 5,000 words every time. Level 1 is ~100 words. Only when relevant does Claude load Level 2, and Level 3 only as needed. This saves tokens and keeps Claude fast.

SKILL.md — The Rules

File & Folder Requirements

RuleDetails
File nameMust be exactly SKILL.md (case-sensitive). Not skill.md, not SKILL.MD.
Folder namekebab-case only. atlas-email ✅ Atlas Email ❌ atlas_email ❌
YAML delimitersMust start and end with ---
No README.mdDon't include README in the skill folder. All docs go in SKILL.md or references/
No XML tagsNo < or > in frontmatter — security restriction
Reserved namesCan't use "claude" or "anthropic" in skill name

SKILL.md size limit: Keep under 5,000 words. Move detailed docs to references/ and link to them.

Critical Skill

Writing Descriptions That Trigger Correctly

Your description determines whether Claude loads the skill. Get this right.

❌ Bad Descriptions

"Helps with projects."

Too vague — won't trigger on anything specific

"Creates sophisticated multi-page documentation systems."

Missing triggers — no user phrases to match

"Implements the Project entity model with hierarchical relationships."

Too technical — no user-facing trigger phrases

✅ Good Descriptions

"Analyzes Figma design files and generates developer handoff documentation. Use when user uploads .fig files, asks for 'design specs', 'component documentation', or 'design-to-code handoff'."
"Manages Linear project workflows including sprint planning, task creation, and status tracking. Use when user mentions 'sprint', 'Linear tasks', 'project planning', or asks to 'create tickets'."

Pattern: [What it does] + "Use when user says..." + [specific trigger phrases in quotes]

Writing Effective Skill Instructions

Recommended Structure

--- name: your-skill-name description: [What + When + Triggers] --- # Your Skill Name ## Instructions ### Step 1: [First Major Step] Clear explanation of what happens. Run `python scripts/validate.py --input {file}` ### Step 2: [Second Step] If validation fails, common issues include: - Missing required fields - Invalid date formats (use YYYY-MM-DD) ## Examples User says: "Set up a new marketing campaign" Actions: 1. Fetch existing campaigns... ## Troubleshooting Error: [Common error message] Cause: [Why it happens] Solution: [How to fix]

Best Practices from Anthropic

Be Specific & Actionable

✅ Run python scripts/validate.py --input {file}
❌ "Validate the data before proceeding"

Use Progressive Disclosure

Keep SKILL.md focused on core instructions. Move detailed docs to references/ and link to them.

Include Error Handling

Tell Claude what to do when things go wrong. "If MCP connection fails: 1. Check Settings > Extensions 2. Verify API key..."

Reference Bundled Resources

Before writing queries, consult references/api-patterns.md for rate limiting and pagination patterns.

Put Critical Instructions First

Use ## Important or ## Critical headers. Repeat key points if needed. Claude reads top-down.

Hands-On

Build Your First Skill in 15 Minutes

Follow these three steps. You can also ask the skill-creator skill to scaffold it for you.

1

Define 2-3 Use Cases

Before writing anything, answer:

  • What does a user want to accomplish?
  • What multi-step workflow is needed?
  • What domain knowledge should be embedded?
  • What phrases would a user actually say?

Example: "Write a LinkedIn post about hiring in Germany, using Atlas brand voice, targeting HR directors."

2

Write SKILL.md

Structure your instructions clearly:

  1. Frontmatter — name + description with trigger phrases
  2. Role — who Claude acts as
  3. Rules — do this, never do that
  4. Templates — output structure
  5. Examples — 2-3 before/after samples
  6. Troubleshooting — common errors & fixes

Pro tip: Include before/after examples. This dramatically improves results.

3

Save, Test, Iterate

Save:

  • Claude.ai: Settings > Skills > Upload ZIP
  • Claude Code: .claude/skills/your-skill/

Test:

  • Ask Claude "when would you use the [skill name] skill?" — it quotes the description back
  • Run 10-20 test queries that should trigger it
  • Verify it doesn't trigger on unrelated topics

Iterate: Skills are living documents. Update based on feedback.

Live Example

Anatomy of a Real Atlas Skill

Let's look at how atlas-email is structured — a Category 1 (Document Creation) skill.

--- name: atlas-email description: > Atlas HXM email skill for outbound sales and marketing. Use when user asks to write cold emails, follow-ups, nurture sequences, drip campaigns, or email copy for Atlas. Triggers: "write an email", "cold outreach", "follow-up email", "email sequence", "nurture campaign". --- # Atlas Email Skill ## Role You are an Atlas HXM email specialist... ## Voice & Tone Rules - Authoritative, inclusive, measured - Lead with insight, not "We at Atlas..." - Subject lines: 6 words max, no clickbait - Never use: synergy, leverage, game-changer ## Email Templates ### Cold Outreach (3-email sequence) Email 1: [Hook with specific insight]... Email 2: [Value proof + social proof]... Email 3: [Breakup + resource offer]...

Why This Works

Description includes trigger phrases — Claude knows exactly when to load it. "cold outreach", "email sequence", etc.

Clear role definition — Claude acts as an Atlas email specialist, not a generic writer.

Specific rules with negatives — "Never use synergy" is more actionable than "use professional language."

Embedded templates — Claude doesn't have to guess the structure. The 3-email sequence pattern is built in.

Works with other skills — Combine with atlas-brand-guidelines for consistent voice, atlas-country for compliance specifics.

Result: Any team member can say "write a cold email about EOR in Germany" and get consistent, on-brand output — every time.

Testing Your Skills — Three Areas

1

Triggering Tests

Does it load at the right time?

  • ✅ Triggers on obvious tasks
  • ✅ Triggers on paraphrased requests
  • ❌ Doesn't trigger on unrelated topics

Debug tip: Ask Claude "When would you use the [skill name] skill?" — it quotes the description back. Adjust what's missing.

2

Functional Tests

Does it produce correct output?

  • Valid outputs generated
  • All API/MCP calls succeed
  • Error handling works
  • Edge cases covered

Method: Run the same request 3-5 times. Compare outputs for structural consistency and quality.

Troubleshooting

Common Issues & Fixes

Skill Won't Upload

Error: "Could not find SKILL.md"

Fix: Rename to exactly SKILL.md (case-sensitive). Verify with ls -la.

Skill Doesn't Trigger

Symptom: Skill never loads automatically

Fix: Revise description — add specific trigger phrases users would actually say. Ask Claude "when would you use this skill?" to debug.

Skill Triggers Too Often

Fix: Add negative triggers: "Do NOT use for simple data exploration (use data-viz skill instead)." Be more specific about scope.

Instructions Not Followed

Common causes:

  • Instructions too verbose → trim, use bullet points
  • Critical rules buried → put them at the top
  • Ambiguous language → be explicit

❌ "Make sure to validate things properly"
✅ "CRITICAL: Before calling create_project, verify: name is non-empty, at least one member assigned, start date not in past."

Large Context / Slow Response

Causes: Skill content too large, too many skills enabled

Fix:

  • Keep SKILL.md under 5,000 words
  • Move detailed docs to references/
  • Keep 20-50 skills max enabled at once

Advanced

Five Skill Design Patterns

Patterns from early adopters and Anthropic's internal teams.

1. Sequential Workflow

Multi-step processes in specific order. Explicit step ordering, dependencies between steps, validation at each stage.

Step 1: Create Account → Step 2: Setup Payment → Step 3: Create Subscription

2. Multi-MCP Coordination

Workflows spanning multiple services. Clear phase separation, data passing between MCPs, validation before next phase.

Figma MCP → Drive MCP → Linear MCP → Slack MCP

3. Iterative Refinement

Output quality improves with iteration. Draft → Quality Check → Refine → Re-validate → Finalize.

Explicit quality criteria + validation scripts + know when to stop

4. Context-Aware Tool Selection

Same outcome, different tools depending on context. Decision tree based on file type, size, or purpose. Fallback options. Transparency about choices.

Large files → cloud storage | Collaborative docs → Notion | Code → GitHub

5. Domain-Specific Intelligence

Specialized knowledge beyond tool access. Compliance checks before action, comprehensive audit trails, governance and documentation.

Payment processing → sanctions check → jurisdiction verification → risk assessment

// To create a new skill: "Use the skill-creator skill to help me build a skill for [your use case]" // To review an existing skill: "Review this skill and suggest improvements" // To iterate after testing: "Use the issues identified in this chat to improve how the skill handles [specific edge case]"
