Chat vs. Cowork vs. Code — When to Use Each

The Claude Desktop App has three distinct modes. Here's how they differ and when each is the right choice.

Feature Chat Cowork Code
What it does Responds to prompts one at a time — Q&A, brainstorming, drafting Executes multi-step tasks autonomously on your files & apps CLI tool for developers — agentic coding in the terminal
File access Upload files to conversation only Direct access to a local folder on your computer Full codebase access via terminal
Scheduled tasks No Yes — runs tasks on a recurring schedule Via cron/hooks
Best for Quick questions, edits, brainstorms, one-off drafts Reports, file organization, research, presentations, data work Software development, debugging, code review
Usage cost Lower Higher (agentic = more tokens) Higher (agentic)
Who at Atlas Everyone — daily driver Marketing, Sales, RevOps, Ops, Enablement Engineering, DevOps, technical Ops

Rule of thumb: Use Chat for simple back-and-forth. Switch to Cowork when you need Claude to do the work — create files, process data, execute multi-step workflows — and come back with finished output.

Setup Guide

Getting Started with Cowork — 5 Steps

Set this up once, and every future conversation starts smarter.

1

Install the Desktop App

Download from claude.com/download. Log in with your Pro, Max, or Team account. You'll see Chat and Cowork tabs at the top.

2

Set Global Instructions

Go to Settings → Cowork → Edit next to "Global Instructions." These persist across every conversation and project. Include your role, team context, and output preferences.

3

Create Your First Project

In the sidebar, find Projects and click "+". Pick a local folder — this is where Claude reads from and saves finished work. Give it a clear name and add project-specific instructions.

4

Connect Your Tools

Go to Settings → Connectors (or the connectors menu in the prompt box). Connect Google Calendar, Slack, Asana, Outlook, SharePoint, or other tools your team uses. Claude can then read emails, pull tasks, and work across apps.

5

Add Skills & Plugins

Install plugins that match your role. Skills give Claude domain expertise — like brand voice, document formatting, or sales workflows. We'll cover these in detail shortly.

Projects

Projects — Your Dedicated Workspace

Projects are the organizational backbone of Cowork. Each project is a dedicated local folder with its own context, instructions, memory, and scheduled tasks.

What Lives Inside a Project

  • Working folder — a local directory on your computer. Claude reads from and saves to this folder.
  • Project instructions — custom rules and context specific to this project (separate from global instructions).
  • Memory — Claude builds knowledge about your work over time. Preferences, decisions, and context persist across conversations.
  • Scheduled tasks — set recurring automations (weekly reports, daily summaries, etc.).
  • Conversation history — past conversations stay scoped to the project for easy reference.

Best Practices for Project Setup

One project per workstream. Don't dump everything into a single project. Create separate projects for "Q1 Campaign," "Sales Enablement Content," "RevOps Reporting," etc.

Add context files to the folder. Drop in brand guidelines, ICPs, messaging docs, templates — anything Claude should reference when working. The more context, the better the output.

Write clear project instructions. Tell Claude who the audience is, what standards to follow, what format outputs should take, and what to avoid.

Deep Dive

Memory & Instructions — Making Claude Smarter Over Time

Global Instructions

Found in Settings → Cowork → Global Instructions. These apply to every conversation and project. Use them for:

  • Your name, role, and team
  • Communication style preferences
  • Default output formats (e.g., "always save as .docx")
  • Tools and platforms your team uses

Example global instruction:
"I'm a GTM Manager at Atlas HXM. I work across marketing, sales enablement, and RevOps. Always follow Atlas brand voice: authoritative, inclusive, measured. Use Gelion/Poppins fonts. Never use green. Save final outputs as .docx or .pptx."

Project-Level Memory

Claude automatically saves patterns, preferences, and decisions to a MEMORY.md file per project. It persists across sessions — no manual setup required.

  • User memories: your role, expertise, how you like to work
  • Feedback memories: corrections and confirmed approaches
  • Project memories: deadlines, stakeholders, decisions
  • Reference memories: where to find external info (Slack channels, dashboards, etc.)

Tip: You can tell Claude "remember that our Q2 campaign launches April 15" or "forget the old positioning doc" and it will update its memory immediately.

Skills

Skills — Persistent Instructions That Never Expire

A Skill is a markdown file (.md) that gives Claude specialized knowledge for a specific type of task. Unlike a prompt that vanishes after a conversation, a Skill persists and activates automatically when relevant.

How Skills Work

  • A Skill is a SKILL.md file stored in your .claude/skills/ folder
  • No code, no API, no build step — just instructions in markdown
  • Claude reads the skill automatically when a matching task is detected
  • Skills can include templates, rules, examples, and reference links
  • Multiple skills can combine for a single task (e.g., brand guidelines + document formatting)

Examples of Atlas Skills

atlas-brand-guidelinesEnforces Atlas voice, colors, logo, tone on all content
atlas-presentationsUses official PPT template for all slide decks
atlas-reportsFormats client & market reports to brand standards
docx / xlsx / pdf / pptxBest-practice document creation for each format

Anatomy of a SKILL.md File

# Content Creator Skill

## Role
You are an Atlas HXM content creator...

## Voice & Tone
- Authoritative, inclusive, measured
- Never use buzzwords: synergy, leverage...

## Output Rules
- Lead with insight, not "We at Atlas..."
- Use active voice, short sentences
- Include specific data points

## Templates
### LinkedIn Post Template
[Hook: 1 line, counterintuitive insight]
[Body: 3-4 short paragraphs]
[CTA: soft, value-oriented question]
[3-5 hashtags]
Skills

Creating Your Own Skills — Step by Step

You don't need to write code. Skills are markdown files with clear instructions. Here's how to create one.

1

Define the Task

What type of work should this skill handle? Be specific. "Write LinkedIn posts for Atlas" is better than "write social media content."

Ask yourself: What instructions would I give a new hire to do this task perfectly every time?

2

Write the SKILL.md

Structure it clearly with sections: Role, Rules, Tone, Templates, Examples, and References. Include "do this" and "never do this" guidance.

Pro tip: Include 2-3 before/after examples showing bad output vs. good output. This dramatically improves results.

3

Save & Test

Save the file to .claude/skills/your-skill-name/SKILL.md in your project folder. Then test it by asking Claude to perform the task. Iterate on the instructions until the output is consistently on target.

Use the skill-creator: Ask Claude to "create a new skill for [task]" and it will scaffold the file for you.

Team tip: Skills are just files in a folder. Share them with teammates by dropping them into a shared project directory or a team Git repo. When everyone uses the same skills, outputs are consistent across the whole team.

Artifacts

Artifacts — From Idea to Interactive Prototype

Artifacts are self-contained pieces of content Claude creates in a dedicated panel — code, documents, apps, charts, and more.

What Artifacts Can Do

  • React apps & components — interactive dashboards, calculators, forms
  • HTML pages — landing pages, email templates, one-pagers
  • SVG graphics — diagrams, infographics, flowcharts
  • Mermaid diagrams — org charts, process maps, timelines
  • Markdown documents — reports, guides, blog posts
  • Data visualizations — charts with Recharts, D3, Chart.js

Sharing Artifacts

Publish any artifact and share the link — recipients don't need a Claude account. Perfect for prototypes, client previews, and team review.

Best Practices

Be specific with your first prompt. The clearer your initial request, the better the first version. Include layout, data, colors, and behavior requirements up front.

Iterate through conversation. Ask Claude to modify specific parts: "change the header to navy" or "add a pie chart for Q1 data." Each request builds on the previous version.

Know the limits. Artifacts get you ~70% of the way to a production app. They're perfect for prototypes, demos, and internal tools — not production-grade software.

Security check. Before publishing, make sure the artifact doesn't contain confidential data, internal metrics, or client information.

Plugins & MCP

Plugins, Connectors, & MCP Servers

These are the three ways Claude extends its reach beyond conversation — connecting to your tools, data, and workflows.

Connectors

Built-in integrations with a graphical setup flow. Connect via Settings → Connectors in the desktop app.

  • Google Calendar, Gmail
  • Slack, Microsoft Teams
  • Asana, Linear, Jira
  • Outlook, SharePoint, OneDrive
  • Salesforce, HubSpot

Once connected, Claude can read your calendar, send messages, pull tasks, and work across apps directly.

MCP Servers

Model Context Protocol gives Claude access to external tools, databases, and live documentation.

  • GitHub, Filesystem, databases
  • Web scraping & data enrichment
  • Custom internal APIs

Best practice: Most teams need 2-3 MCP servers (e.g., GitHub + one domain-specific) plus a few custom Skills. Don't overload — each server uses context tokens.

Plugins

Bundles that package multiple customizations: skills, MCP configs, slash commands, and hooks into a single installable unit.

  • Install from the plugin marketplace
  • Or create your own for team use
  • Sales plugins: call prep, pipeline review
  • Marketing plugins: content calendar, SEO

Search the plugin registry from within Cowork to find plugins built for your role.

Best Practices

10 Best Practices for Getting the Most from Claude

1. Be specific, not vague. "Write a 200-word LinkedIn post about EOR compliance in Germany targeting HR Directors" beats "write a LinkedIn post about compliance."

2. Use Projects — always. Never work in a bare conversation when you could use a project with context files and instructions.

3. Front-load context. Drop brand docs, ICPs, past examples, and reference materials into your project folder before you start asking for outputs.

4. Iterate, don't restart. If the first output is 80% right, ask Claude to fix the 20% — don't start a new conversation.

5. Give feedback to build memory. Say "that was perfect" or "never do X again" — Claude remembers and improves over time.

6. Use scheduled tasks for recurring work. Weekly competitive briefs, daily pipeline summaries, monthly report templates — set them once, get them forever.

7. Combine skills for complex tasks. "Use the brand guidelines skill AND the presentation skill to build a deck" produces better results than using either alone.

8. Use Chat for quick things. Don't burn Cowork tokens on a simple question. Chat mode is faster and cheaper for brainstorming and Q&A.

9. Review before sharing. Always check Claude's output for accuracy, brand compliance, and confidential data before sending externally.

10. Share skills with your team. If you build a skill that works well, share the file with teammates so everyone benefits from the same quality bar.

Prompting

Prompting Claude — Quick Reference

The quality of Claude's output directly reflects the quality of your input. Here's a framework.

The CRAFT Framework

Context — Who you are, what project this is for, who the audience is

Role — Tell Claude what role to play: "You are an Atlas content strategist"

Action — What specifically you want done: "Write a 300-word blog intro"

Format — How you want the output: "As a .docx with H2 headers"

Tone — Specify the voice: "Authoritative but not formal, per Atlas brand guidelines"

Good vs. Weak Prompts

WeakStrong
"Write a blog post about EOR" "Write a 600-word blog post targeting HR Directors at mid-market companies (500-2000 employees) considering their first international hire. Focus on the top 3 compliance risks of hiring in Germany without a local entity. Use Atlas brand voice. Save as .docx."
"Make a presentation" "Create a 10-slide .pptx deck for our Q2 sales kickoff. Audience: AEs and SDRs. Cover new messaging, updated ICP, competitive positioning vs. Deel. Use the Atlas PPT template."

For more prompting guidance: docs.claude.com — Prompt Engineering

Automation

Scheduled Tasks — Set It and Forget It

One of Cowork's most powerful features. Claude runs tasks on a schedule — no manual prompting needed.

How to Set Up

In any Cowork conversation, ask Claude to create a scheduled task. You can also go to your project settings to manage existing schedules. Claude will confirm the task, frequency, and output location.

Example: "Schedule a weekly competitive intelligence brief every Monday at 8am. Save it as a .docx in this project folder."

Marketing Ideas

  • Weekly competitive landscape summary
  • Daily content calendar reminder with draft ideas
  • Monthly campaign performance rollup
  • Bi-weekly SEO keyword tracking report

Sales & RevOps Ideas

  • Daily pipeline health snapshot
  • Weekly stale-deal alerts
  • Monthly win/loss analysis summary
  • Quarterly territory planning data refresh

Requirement: Cowork must be running (desktop app open) at the scheduled time for the task to execute. If missed, it runs at the next available time.

Important

Security, Compliance & Data Handling

Claude is a powerful tool, but it requires responsible use — especially at a company that handles global HR and compliance data.

What NOT to Share with Claude

  • PII / employee data — social security numbers, passport numbers, salary data, medical info
  • Client contracts & financials — unless explicitly approved by Legal
  • Credentials & passwords — API keys, login credentials, tokens
  • Confidential strategy docs — board materials, M&A information, unreleased financials

Rule of thumb: If you wouldn't email it to an external consultant, don't share it with Claude.

Best Practices

  • Review before sharing externally. Always check Claude's output for accuracy and unintended data exposure before sending outside Atlas.
  • Use Team/Enterprise plans for admin controls, SSO, and data governance policies.
  • Don't publish artifacts with internal metrics, client names, or strategic data.
  • Check connector permissions. When connecting tools like Slack or email, understand what data Claude can access.
  • Report concerns to your manager or IT if anything seems off.
